# CivitaiFlow 22.7.1 — Interface Reliability Patch

**Release class:** stabilization / compatibility patch  
**Target:** Stable Diffusion WebUI Forge  
**Date:** 2026-09-03

## Executive summary

22.7.1 fixes a class of Forge/Gradio compatibility failures where CivitaiFlow loaded functionally but rendered as an unstyled extension: oversized SVG branding, a browser-default-sized Civitai iframe, weak layout constraints, stale release identity, and lifecycle widgets mixed into the API credential card.

The patch treats UI reliability as a runtime contract rather than a theme assumption.

## What changed

### Premium shell moved to a reliable injection path

`javascript/premium_shell.js` now injects the product shell stylesheet directly into the browser document head and marks the actual runtime wrappers generated by Gradio.

The shell enforces:

- bounded 340–410 px desktop control rail;
- fluid browser workspace with `min-width: 0` and no inherited prose/max-width constraint;
- workstation-sized embedded Civitai frame;
- compact brand mark;
- premium cards, spacing, typography and status treatment;
- responsive medium/narrow layouts;
- dedicated **Library & lifecycle** surface.

### Critical dimensions now have a second fallback

`scripts/zzzzz_civitaiflow_release.py` late-binds the final 22.7.1 brand and embedded browser builders with critical inline dimensions.

This protects the two most damaging visual failures even if a future Forge/Gradio build ignores extension CSS again.

### Version drift removed from Library Intelligence

`javascript/library_status.js` no longer forces the visible product badge back to `v22.5`.

The final release layer owns the 22.7.1 product identity, while the premium shell continuously heals the visible badge if an old runtime fragment attempts to mutate it.

### Current Civitai account route

The final release layer routes **Get API Key** to:

```text
https://civitai.com/user/account
```

The existing browser-side Companion interception remains the preferred path because it opens the page in the user's actual browser profile.

### Browser Bridge reliability

Browser Bridge 0.3.0 now discovers common local Forge ports:

```text
7860
7861
7862
7863
```

on both `127.0.0.1` and `localhost`, then remembers the working base.

### Release diagnostics

New loopback endpoint:

```text
GET /civitaiflow/api/release
```

returns the product release, premium shell generation and Browser Bridge version.

### CI regression contracts

The validation workflow now checks the new Python and JavaScript layers and executes `tests/test_release_contracts.py`.

The contract suite guards:

- 22.7.1 identity alignment;
- removal of the stale `v22.5` badge override;
- critical iframe/logo sizing rules;
- current Civitai account route;
- Browser Bridge port discovery and manifest version;
- deterministic late-load order of compatibility layers;
- presence of the local release endpoint.

## Root cause addressed

The broken layout was not evidence that the iframe or Civitai website itself had failed. JavaScript-injected toolbar styling was present while the base extension styling was absent. That isolates the failure to the Gradio/nested-Blocks CSS path.

22.7.1 keeps the old CSS as backward-compatible fallback but no longer trusts it as the only styling mechanism.

## Upgrade procedure

```text
1. Pull/update the CivitaiFlow extension.
2. Stop Forge completely.
3. Start Forge again.
4. Reload Browser Bridge in Edge/Chrome if you use it.
5. Hard-refresh the Forge browser once.
6. Open CivitaiFlow and verify v22.7.1.
```

Do not judge a Python-layer update from a browser tab refresh without a Forge restart.

## Acceptance criteria

A local runtime candidate is acceptable when all of the following are true:

- CivitaiFlow mark is compact;
- visible release is `v22.7.1`;
- embedded Civitai fills the browser workspace;
- no large unexplained blank region exists because of a default-size iframe;
- Library Intelligence and Model Lifecycle render in their dedicated runtime card;
- Companion opens a normal top-level Civitai window;
- Get API Key reaches the current account page;
- library indexing reaches a stable state;
- Browser Bridge can reach Forge on a supported local port;
- GitHub `validate` is green.

## Remaining runtime caveat

GitHub CI does not boot a real Forge + Gradio instance. A green CI run proves syntax and release contracts, not final visual rendering in the user's installed Forge build.

For that reason 22.7.1 requires the local smoke test documented in [TESTING.md](TESTING.md) before it should be called fully runtime-verified.

See also [TROUBLESHOOTING.md](TROUBLESHOOTING.md).
